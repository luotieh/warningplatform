# 历史事件综合报告

历史事件页在查询结果标题右侧提供「生成综合报告」。范围固定为最近一次已提交的 IOC、可选 IOC 类型和被攻击方查询，包含全部时间、全部分页和已归档事件；未提交的表单编辑不改变报告范围。

## 独立链路

1. `POST /api/traffic/events/history/report` 接收 `{ioc_value, ioc_type?, victim?}`，仅由人工点击触发，在当前请求中执行并返回完整报告。
2. 通过与历史列表相同的精确匹配逻辑读取一次事件集合。不会调用单事件分析，不修改事件报告、概率、消息或分析版本。
3. 确定性生成统计快照：事件总数、已知聚合命中数及缺失计数、首次/末次活动、每日新聚合事件数量及其资产/类型分布、总体资产/类型/保存协议分布、未收敛事件数量。
4. 独立综合报告提示词只接收统计快照；不发送原始报文、逐条报告、单事件概率或来源 ID 列表。模型输出总体判断、历史活动轮廓、关联特征、趋势与风险走向、处置观察建议及数据边界。
5. 通过现有 aggregation record 存储机制持久保存已完成报告、完整统计快照和来源事件 ID；不新增数据库表。
6. 页面等待调用返回，展示经过现有 Markdown 消毒工具处理的报告，支持下载 Markdown 正文、统计快照和来源索引。切换查询范围时丢弃旧请求的页面响应。没有后台任务、轮询、自动或定时触发。

## 统计边界

- 所有日期以北京时间统计。每日新增事件仍按首次活动日期统计；另按保存命中时间戳统计每日活动、活跃事件及端点/协议/资产分布，跨日事件按实际记录分别计入，不插值，不代表完整会话流量。
- 命中次数缺失时单独计数，不擅自补一。未收敛事件的统计仍可能变化。
- 每日资产和类型分布可描述观测对象的变化；协议标签不能证明实际连接成功。
- 采集覆盖未知、当天不完整、样本不足时，不得把计数变化推断为真实攻击升级、消失或处置成功。DNS 命中不等于成功连接，历史重复不自动构成 C2，不平均单事件概率。
- 当前流程基于保存事件、固定版本命中快照、IOC情报标签和结构化证据结论（按事件去重），不重新抓取 PCAP 或重新运行单事件证据库。流量细节和精确会话行为不足时，综合报告应明确说明。
- 模型统计输入最多 180,000 字节，超限明确失败并提示按被攻击方缩小范围，不静默截断。请求生成超时五分钟，请求取消后取消模型调用；部署反向代理的读取超时需覆盖报告生成耗时。模型空输出或长度截断视为失败。
- 报告持久保存于服务端；历史页按相同查询范围列出已保存报告，可刷新、打开和下载，无需重新调用模型。GET `/api/traffic/events/history/reports` 查询列表，GET `/api/traffic/events/history/reports/:reportID` 读取原报告。旧版部分命中明细、不可用快照与完整保存记录分别标注；完整保存记录不等于全网采集完整。

## 验证

- 后端：`go test ./traffic -count=1`
- 前端历史页行为：`node scripts/test-event-history.cjs`
- 全量前端类型检查：`pnpm typecheck`（仓库其他模块当前有既存类型错误，需单独处理）。
