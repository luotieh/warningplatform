# 性能比较

基线为`222c086ac69418539369e3b3b66180f4ccfc4382`。相同Go1.26.3、同一测试脚本、24个受控HTTP请求，各15次冷运行与15次热运行。模型为确定性stub，不代表真实推理性能。基线只调度一期5F/4S，新版59F/23S，工作量不同。

| 整体耗时 | 旧版 | v2 |
|---|---:|---:|
| 冷P50 | 39.266ms | 145.587ms |
| 冷P95 | 49.307ms | 163.397ms |
| 热P50 | 27.278ms | 121.813ms |
| 热P95 | 28.686ms | 126.000ms |

新版每次冷读取20,210字节、25页；热运行原始读取、JSON、帧及HTTP解析均为0。旧版冷读取相同，热读取页也是0。单独改变模型版本，两版额外原始读取均为0，不能宣称数据库取数总量改善。

## 重复解析

在隔离导出的基线副本，仅在实际解析调用处增加计数，未改算法。计数补丁见`pipeline-v2-parser-instrumentation.patch`，结果见`pipeline-v2-baseline-parses.json`。新版计数在pipeline metrics中。

| 实际解析：24个请求 | 旧版 | v2 |
|---|---:|---:|
| 帧解码 | 144 | 24 |
| HTTP请求解析 | 48 | 24 |
| DNS解析（本HTTP负载） | 0 | 0 |

该负载重复帧解析减少120次，HTTP解析减少24次。DNS及其他负载不能从本表外推。

## 内存、模型及统计限制

旧版冷/热每次平均累计分配约29.37/16.23MiB，新版约121.58/70.97MiB。运行结束后采样HeapAlloc最大值，旧版约11.50/12.86MiB，新版约29.33/28.98MiB。这些是分配量及采样值，不是进程峰值RSS，不构成真实峰值内存验收。

15次冷运行stub调用合计旧版360、新版615；热运行均0。新版逐次F、独立F、S规划/执行/校验、C、归一化耗时保存在`pipeline-v2-performance.json`各sample的`pipeline.metrics.stage_ms`中。毫秒粒度的0不代表未执行。旧版无同样的单层探针，不能补造旧版F/S分层P50/P95。

实际模型输入Token和真实推理P50/P95不可得；未配置目标分词器，估计值不计为实际Token。S阶段计时包含规划、序列化、缓存及stub响应校验，不能称为真实推理耗时。

已验证解析复用，整体吞吐与分配表现仍有回退；生产容量及进一步减少任务规划、缓存序列化成本仍需验收。
