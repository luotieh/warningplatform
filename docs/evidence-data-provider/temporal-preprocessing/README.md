# 前三项时间证据的预处理修复

已接通：`平台原始命中 → 报文核验/协议解析 → 独立联系去重 → 历史时间序列 → PreparedBundle → 原有F算法`。采集层负责读数据，预处理层仍可断开数据库后离线运行。

## 2026-10-20：前两项窗口默认完整

按业务要求，Provider预处理生成`phase_one_materials.temporal_window_coverage`，其中`basis=default_assumption`。此策略仅作用于`F_BEACON_JITTER`和`F_FIXED_DAILY_WINDOW`：缺少独立窗口证明时默认完整，计算结果的`limitations`及供应审计均保留假设说明。

- 受控数据的20个当前独立联系、4个自然日材料，已能执行这两项计算。
- 当前/历史的明确截断、解析或绑定缺失仍限制对应Scope；历史查询截断、快照未读齐或预算跳过仍阻止扩展时间线认定完整。历史不足不影响已有足够样本的当前抖动计算。
- 至少16个同类独立联系、至少3个自然日等原有门槛保持不变；默认完整不会补造联系或历史。
- HTTP、Network、群体材料及全局已核验覆盖字段保持原值。`F_MULTI_DAY_PERSIST`不使用这个新策略。
- 新策略在重新预处理collection后生效；旧Bundle的回放仍保留其原有输入。下方表格和`validation.json`记录此前修复基线，其中“必须提供窗口证明”的约束由本节替代。

| 证据项 | 本次修复 | 仍需满足的数据条件 |
|---|---|---|
| `F_BEACON_JITTER` | 从完整HTTP请求、TCP发起或DNS问题生成`id/time/kind/scope/ioc_type/value/hit_id/snapshot`；相同报文重复告警不重复计数 | 同一资产/设备/端点/IOC/联系类型至少16个独立样本；无已知缺失时窗口默认完整 |
| `F_FIXED_DAILY_WINDOW` | 采集冻结历史快照的原始命中，离线核验同一资产、设备、端点及IOC；事件摘要的关联字段缺失时，可凭真实报文恢复关联 | 至少3个自然日的独立联系；无已知缺失时窗口默认完整 |
| `F_MULTI_DAY_PERSIST` | 将当前及可信历史联系送入原有跨日统计；已有足够活跃日时，允许在部分覆盖下形成局部阳性 | 达到原有策略的活跃日阈值；不足时保留覆盖不足，不能作阴性排除 |

`inputs.observations`的真实类型是HTTP/DNS等协议语义观测，没有通用联系时间字段。它现在随报文解析填充；这三项时间规则实际使用的是`phase_one_materials.contacts`，不能把语义观测条数当作联系次数。

## SYN与HTTP联系的精确去重修正

取消“同一资产/端点/IOC出现HTTP就排除全部SYN”的处理。现在联系携带已核验报文的TCP流标识、序列号及有效的采集会话起始时间；只有流、会话起始时间、Scope、IOC一致，HTTP序列号紧随SYN，且请求时间不早于SYN时，才用该HTTP请求替代对应SYN。

无法关联的SYN保留为`tcp_initiation`，HTTP请求保持`complete_http_request`；时间算法按类型分开计算，不合并样本数。来源会话信息不足时也保留原联系。跨事件材料合并后对当前、扩展时间线分别去重，历史联系不混入当前集合。

去重不再添加`syn_excluded_from_http_request_timeline`缺失标记；清理旧标记时仍保留明确截断、解析失败和绑定失败。重用相同五元组及序列号、但会话起始时间不同的联系，不合并为重传。

本地真实归档回放（非线上验收）：874条命中的事件由169个联系恢复为194个，HTTP联系保持168个，恢复25个此前被范围级排除的SYN，另有其他端点的1个SYN。HTTP及恢复SYN各自的抖动计算均可执行，结果均为有效阴性；固定时点仍因不足3个自然日而缺失。6条命中的另一事件仍为3个联系，跨日持续的已有阳性保持。

回归用例覆盖连接匹配/不匹配、会话复用、序列号回绕、重传、同连接多请求、跨事件合并、实际缺失保留及Bundle序列化。

## 此前修复基线（窗口策略调整前）

- 受控报文：21条当前告警去重为20次完整HTTP联系，加入3次可信历史联系后覆盖4个自然日；跨日持续阳性。历史事件摘要缺少设备字段时，可用冻结报文恢复关联。
- 两份真实归档事件：6条命中生成3次独立联系；874条命中生成169次独立联系及128份协议观测（达到已有语义材料数量上限）。第一份归档在一个端点上有跨日持续阳性。
- 真实归档只加载这两份已保存事件；不是生产数据库验收，也未宣称已覆盖平台全部历史。
- 上述真实及受控材料都没有独立的整段通信覆盖证明，所以抖动信标、固定时点仍返回`unverified_coverage`。未修改算法阈值，未将快照行数相等升级为完整网络可见性。
- 四份既有摘要场景，在相同执行配置下，归一化规则字段与修复前一致，仅排除已变化的输入摘要。它们没有新增原始报文，不能仅靠预处理产生额外的真实联系。
- 后端全量测试、定向测试、`go vet ./...`及构建通过。所有操作本地只读，未调用真实模型。

## 实现位置

- `evidence_provider_collection.go`：历史原始命中读取、冻结水位、时间范围及独立的历史行数/字节预算；缺少来源和预算不足的原因保存在collection。
- `evidence_provider_assembly.go`：复用现有报文解析器，兼容嵌套IOC，保留摘要数据，生成联系及协议观测。
- `evidence_provider_timeline.go`：纯离线历史绑定和去重；历史报文不混入当前HTTP/语义来源。
- `phase_one_materials.go`：补充单报文完整性门槛，截断SYN/DNS也不能成为独立联系。
- `evidence_contract_schema.go`：修正`json.RawMessage`被误当作base64字节串的问题，使真实应用对象可通过Bundle序列化校验。

完整统计见`validation.json`。可重跑的用例为`TestProviderTemporal*`；真实归档用例默认跳过，仅在设置`PROVIDER_TEMPORAL_ARCHIVE`指向已有本地归档时运行，不包含网络读取。
