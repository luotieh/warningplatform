# 研判报告正文组织 v1.4

本次按用户提供的实际DOCX调整报告专用生成路径。报告目标是向资产责任方说明事件、判断、风险和防护，证据库提供依据，不把核验清单当报告正文。

## 正文固定顺序

1. 研判结论：先给结论，再用简洁因果解释关键行为、关联和判断；保留有依据的研判概率。
2. 事件总览：北京时间窗口、涉及资产、源IP/端口、目的IP/端口、协议、告警命中次数、去重物理报文和IOC来源、活动、置信度。完整固定快照汇总，不能把命中次数写成会话数量。
3. 关键证据：与结论相关的证据编号加一句自然语言事实，不输出英文指标或执行状态。支持事实、实际反证和已证实替代依据保留；基础绑定信息不单独凑关键证据。
4. 风险分析：exposure写实际证据支撑的风险入口/防护对象；impact以条件方式解释这种攻击对资产、账号、数据和服务的影响。必须绑定证据编号，不把风险后果写成已发生损害，也不据类型标题编造攻击链。
5. 建议处置：面向资产责任方，给出实际对象、核查位置、防护动作及阻断/隔离的触发条件；与前述风险对应。

## 实现和兼容

报告schema为evidence-report-1.4。总览保存在不可变报告bundle中，来自全部ReportMaterialObservation，而不是单条代表报文；完整五元组分布也进入可引用的观测证据，防止本机端口无法通过数字核验。

模型输出新增risks数组，校验引用、条件表述、数值来源和成功性越界。完整核验表、模型研判依据、技术缺项、来源索引和执行进度移至附录；DOCX正文与附录分页，五元组表设置对应列宽。

冻结1.3.2及更早渲染器，旧报告不重新套新版格式或改写结论；读取历史报告仍绑定原snapshot、summary和原文。要得到新版研判内容，需要在模型服务可用时生成新版本报告。

本次不改事实算法前提、证据权重、采集、数据库、告警业务、全局模型配置或前端。不恢复用户已停止的独立报告评审。

## 验证边界

回归覆盖五部分顺序、所有五元组保留、物理报文去重、北京时间、技术记录不进入正文、附录完整保留、风险必须绑定且条件表述、历史1.3.2报告兼容，以及报告API鉴权、指定版本和DOCX导出。

模型服务额度问题未解决，格式和系统测试不代替180实际新报告生成或内容验收；不手改用户原DOCX冒充新生成报告。
