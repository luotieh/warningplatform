# 研判报告优化10.13：配置与核验说明

## 改动与边界

本次增加正式报告的专用容量参数、文件日志和真实材料核验工具；新报告必须有证据支持的整数概率，报告文档、专家消息、快照标记和事件列表概率在同一事务中发布。事务任一写入失败均回滚，不覆盖旧成功报告和概率。旧报告读取与导出继续使用兼容校验。

证据算法、前提、阈值、原有权重值和选择规则均未调整；普通聊天与语义调用的输出预算保持原行为。语义调用仅增加可选日志，实际模型客户端保持独立预算。

## 报告专用配置

在现有配置文件的`[traffic]`段增加所需项，不能复制整个示例覆盖原配置。环境变量优先；每次正式报告读取，修改文件后下一次正式报告生效，无需修改前端。

```toml
[traffic]
# 下列项为示例。输入6000是完整提示词预算，不是模型总窗口。
report_input_token_limit = 6000
report_output_token_limit = 6000
# 未核实窗口时不填／填0；不能以预算代替模型能力证明。
report_context_window_tokens = 0
report_token_safety_margin = 0
report_log_enabled = true
report_log_dir = "data/repLogs"
report_log_retention_days = 30
```

对应环境变量：`REPORT_INPUT_TOKEN_LIMIT`、`REPORT_OUTPUT_TOKEN_LIMIT`、`REPORT_CONTEXT_WINDOW_TOKENS`、`REPORT_TOKEN_SAFETY_MARGIN`、`REPORT_LOG_ENABLED`、`REPORT_LOG_DIR`、`REPORT_LOG_RETENTION_DAYS`。

未设置输入预算时保留原完整提示词估算上限20000、user估算上限18000和100000字节保护。未设置输出上限时继承当前客户端设置，通常为6000。显式输入预算计入system及12个估算封装token；user可用量扣除这些占用。显式预算的字节保护为预算×8，最多16MiB；这是程序保护，不是模型窗口。

已知窗口时，输入预算＋输出上限＋安全预留不得超过窗口。负数／非法参数直接报错，不偷偷回落。配置未核实窗口不会被日志标为“容量已验证”。扩大输入只影响报告专用路径；材料超限仍保留准备内容并明确记为未发送，不新增静默丢弃核心事实的路径。

初次与一次格式纠正调用遵循相同完整输入预算，纠正调用附带旧输出，因此也会超预算；超过时明确记录未发送，不无限重试。现有64KB报告JSON校验上限、模型客户端4MiB响应保护和HTTP超时仍存在；调大token不代表这些保护也自动改变。

6000→8000→10000是受控验证档位，不能一次同时提高输入与输出。本次未修改180配置、未开展模型容量压力探测；模型真实最大窗口仍需服务端部署参数或受控真实调用核实，不能根据20tps或配置值推断。

## 日志位置与内容

默认路径以应用工作目录为基准：通常容器内`/app/data/repLogs`。日期采用北京时间。目录为`日期/事件ID/随机任务ID`，目录权限0700、文件权限0600；程序不会把日志加入Git。

每份日志记录任务入口类型、事件、快照、报告版本、构建commit、模型、容量参数及证据数量，保存完整材料快照、算法和语义结果、归一结果、选择映射、实际权重策略、实际请求／响应、实际usage和概率发布结果。摘要在`summary.md`，完整证据在对应JSON。

`llm-call-*-request.json`从客户端实际请求构建边界写入，包含真正的payload，无认证头／API密钥。`dispatch.json`区分准备和尝试发送，响应记录实际返回；初次／纠正／协议回退均有独立编号。服务不返回usage时使用`usage_available=false`及`usage=null`，不伪造实际零消耗。支持记录Chat Completions及Responses真实usage。

语义层同时保存任务适配器输入与实际传输日志；注入的测试模型只有适配器记录，不伪装为网络请求。缓存命中只记录已使用缓存的版本和结果，不制造新调用。

日志失败只产生`[repLogs]`告警，不阻断报告。磁盘完整性异常看`manifest.json`的`log_write_errors`及`log_complete`。资料中确有真实报文、地址或正文时，只能交授权内部人员查看；完整请求不公开返回给浏览器。

部署时将专用宿主机目录映射到`/app/data/repLogs`，避免容器替换后丢日志。本次未部署，也未修改180现有挂载。

## 证据数量口径

材料覆盖日志分别列出59类事实规则、23个语义槽位和新增观察项，实际执行实例可能超过82。缺项占位、多个scope或槽位任务都会增加归一实例数，这个数不代表可用于恶意判断的证据数。

`completed_fact_type_count`：当前真实快照中正常算出observed或not_observed的规则类型数；负向结果也是计算完成，但不是恶意证据。

`gap_free_fact_type_count`：上述结果中额外满足quality=complete、eligibility=eligible的类型数。partial历史记录可形成有来源的活动下界，但不计入“无缺口完整计算”。

`validated_semantic_slot_type_count`：实际执行并通过校验的槽位类型数；计划不算完成。材料依赖、计划执行、结果、缺项和实际选中内容均可追溯。缺材料不直接标成不适用；无法独立确认适用性时记录未建立适用性，不拿缺失当反证。

`gap_free_semantic_slot_type_count`采用更严格的日志统计：已接受、非重复、没有声明gaps且任务材料未截断。该统计不改变语义门槛；已接受但带限制的解释仍保留，不能把“不计入无缺口数量”当作执行失败。

权重仍为原有相对影响：普通1.0、满足条件的默认时段观察1.15、满足条件的时间规律1.25；没有确定的概率计算公式。日志记录输入权重、同源／非累加关系、模型结构化支持／反向理由、概率及校验发布，不记录或伪造模型隐藏思维链。

## 工具使用

以下命令在后端目录执行：

```sh
# 完整事实与槽位依赖目录：不读取数据库、不调用模型。
go run ./traffic/cmd/evidence-check -catalog

# 实际材料和归一核验：只读数据库，不调用模型；显式写本地诊断文件。
go run ./traffic/cmd/evidence-check -event <真实事件ID> \
  -rep-logs data/repLogs -output actual-evidence.json

# 统计每个事件最新日志的完成类型并集，保留事件集合与任务类别。
go run ./traffic/cmd/report-logs -root data/repLogs > availability-summary.json

# 显式清理30天前已完成任务。默认不会在报告路径自动递归清理。
go run ./traffic/cmd/report-logs -root data/repLogs -prune-days 30
```

清理仅处理带本程序根标记和完成时间的任务，保留运行中任务，不跟随子目录符号链接，删除前核对路径仍在指定根目录内。修改保留天数后，维护命令需同步使用该天数；参数不是已自动调度的清理任务。
