# 真实事件快照接入证据模块

## 当前已接通的链路

`runAnalysis → prepareReportInput → 固定版本的EvidenceSnapshot → SnapshotEvidenceInput → evidence.Engine → SemanticEngine按需解释及校验 → 原有报告模型`

`PrepareReportEvidence`提供同一准备流程的纯上下文入口；报告主流程同时取回资产说明，复用已读取的资产清单。

初报、终报和手动刷新共用这个入口。输入来自现有Store：生产MySQLStore读取`traffic_event_hits`和`traffic_hit_revisions`，MemoryStore执行同样的契约用于测试。代码不需要测试夹具，也不从界面预览或模型回答构建事实。

报告入口现在选择全部59项事实规则，适用且材料充分的执行，不足的保留逐项原因；模块直接调用的nil选择仍兼容原来两项默认规则。23个语义槽位现已接入同一报告流程，首次计算共用命中读取，原文材料按需批量调用并独立校验、缓存；详见[EVIDENCE_SEMANTIC_REPORT.md](EVIDENCE_SEMANTIC_REPORT.md)。补充输入与排错说明见[EVIDENCE_INPUT_COVERAGE.md](EVIDENCE_INPUT_COVERAGE.md)。

可信来源登记已接入同一流程：按完整范围/时间自动匹配、生成当前快照补充输入，审核历史和源内容哈希可追溯；只读验收命令复用该流程，强制冷计算且不调用模型。配置方法和现场数据限制见[EVIDENCE_SOURCES.md](EVIDENCE_SOURCES.md)。

## 怎样复用资料、控制查询

1. 报告只读取一次已发布快照，随后将同一对象交给适配器和报告摘要构建函数。
2. 快照里的代表样本最多48条，不是算法输入。适配器按`Sources + Watermark`每页500条读取原始命中，全部所选规则共享同一份输入。
3. 有修订时，每页只增加一次`HitRevisions`批量查询，并限定`RevisionWatermark`。未修订的事件不查询修订表；算法循环中没有数据库读取。
4. 资产清单读取一次，所有命中在内存中匹配；原有报告的资产说明也使用同一份清单。适配器不按命中调用资产查询。
5. 完整结果缓存在`traffic_aggregation_records`的`evidence_result`记录中。同一版本再次生成报告不重复读取命中。

首次事实计算的命中查询数量约为`ceil(N/500)`，整页边界可能多一次空页确认；有修订时增加相同数量的非空页修订查询。它与所选算法数量无关。501条命中同时选择全部59项的测试固定为3次命中分页读取，没有逐条修订读取。

聚合快照重建也改为使用相同的批量修订读取，避免其原有逐条修订查询。其他分页展示和附件路径不在本次改动范围内。

## 真实输入包含什么

| 输入 | 来源与处理 |
| --- | --- |
| 事件ID、快照版本 | 已发布的事件快照 |
| 时间、命中ID | 服务端规范化后保存的不可变命中记录 |
| 设备ID | 保存记录中的采集设备标识；缺失不计算 |
| 资产身份 | 启用的服务器资产清单匹配，不能来自客户端的asset_id或verified标记 |
| 端点 | 对端IP、实际端口和传输协议；请求与应答方向交换后保持相同身份 |
| 包数 | 原始记录中的整数；缺失、负数和无效数不补零 |
| HTTP元数据 | 已保存app中的完整URL、方法、UA及通信标识；只有路径时，需真实HTTP请求原文证明Host和协议，不能按端口猜测URL |
| DNS元数据 | 已保存的查询、应答及明确提供的rcode；没有rcode不假设成功 |
| 网络记录 | 实际对端及端口；仅完整抓包的合法payload_hex可用于载荷字节数 |

`app`中的正文仍是样本，不能证明完整性。适配器新增原始HTTP报文解析，只有完整字节、合法消息边界及Content-Length/chunked读取完成才能获得正文长度和字段名；事实输入中的字段值立即脱敏，编码特征在脱敏前由确定性代码提取；报告语义适配器在同次扫描中单独保留实际原文，明确标记raw模式，不把事实字段脱敏冒充整份报文脱敏。缺帧、残缺正文、不支持的嵌套结构和多消息均保留诊断。DNS从完整报文读取rcode，查询报文不当作成功应答；真实Ethernet帧可补充载荷，但必须匹配流五元组。

外部基线、历史定谳、战役/当前阶段证明、完整群体成员、授权任务、TLS信任资料和独立情报来源元数据可通过后端独立的快照补充记录接入。这是输入桥接能力；当前仓库没有这些来源的完整自动采集任务，没有配置补充记录时仍返回缺失。不能把探针verified标记、人工通报审核approved/rejected或模型判断升级成独立证明。

## 归属和数据完整性

- 一端唯一命中启用资产清单、另一端未命中时，才形成当前适配器支持的资产/端点范围。
- 两端均已登记、均未登记、多个同等精度登记冲突时，不能根据IOC标签、victim_target或报文方向强行选一端。
- 先使用精确地址；否则选择唯一的最具体CIDR。CIDR登记标识加实际IP区分其中不同主机，不能把整个网段当作一台资产。
- 读取条数必须等于固定快照Count；成员数不一致、读取失败、非法JSON或取消执行返回错误，不生成伪完整结果。
- 部分命中无法归属时，记录未绑定数量并将覆盖标为partial。没有任何可绑定记录时，返回明确的unavailable原因。
- `coverage=complete`仅表示该快照内已保存命中读取完整，不代表该设备的全部网络通信。
- 原始包是否截断未知时，CaptureTruncated保持未知。缺少包数或完整性证明，周期性规则可以返回missing，而不是伪造成立/不成立。

## 资源边界

报告默认采用`DefaultSnapshotEvidenceOptions`：最多20000条命中、最多16 MiB原始资料。预算是集中取数的上限，不是每项规则各自的预算。

新增默认256个资产/端点/设备范围上限，防止全部59项对大量范围形成无界结果；超过记录`snapshot_scope_budget_exceeded`，不使用已读部分产生结论。完整单消息最大1 MiB、补充记录最大2 MiB、详细输入问题最多128条，同时保留总数及省略数。范围上限可由后端调用者显式调整。

超过命中上限，在查询命中前直接记录`snapshot_hit_budget_exceeded`；读取过程中超过资料上限，返回`snapshot_input_budget_exceeded`，不对半份输入计算。不使用代表样本冒充全量记录，原有报告统计仍可继续使用。

服务调用可显式设置其他预算及规则集合。大事件异步计算、统一调度配置和全局并发控制属于后续工作，本次不隐藏强制全量扫描。

## 缓存与审计

缓存键包括事件ID、快照版本、命中/修订水位、规则版本、适配器版本、参数、选择及预算、资产清单内容。新增命中、修订、修改参数或资产登记变化都不会复用旧结果。

补充记录的完整内容及加载状态也进入缓存键，不能只靠调用者声明的版本。补充来源暂时读取失败时，现有事实仍执行，但本次结果不缓存；下次报告重新读取。损坏缓存自动重算。核心命中读取失败时，不发布算法结论，记录故障并保留原报告统计。取消执行正常向上传递。

完整结果保留SourceIDs、Dependencies、指标、阈值、限制和适配清单；Dependencies包含快照来源及资产清单版本指纹。报告input_manifest保存evidence_result_key，能够定位本次完整结果。

报告只投影最多8条事实，并进一步约束在2400字符内，按整条省略，记录total_findings和omitted_findings；优先保留成立事实，其次缺项，再次不成立。整个上下文仍遵守既有6000字符上限。缓存键、登记版本指纹和原始命中ID不传给报告模型。

这里是事实摘要的第一次接入；它不代替实际tokenizer、语义解释的统一报告投影、完整复核页面或缓存保留/清理策略。

## 验证

测试覆盖通过正常摄入流程写入Store、压缩代表样本与全量输入区别、请求/应答归属、注册身份冲突、缺包数/未知截断、数据预算、历史修订水位、缓存复用与资产变更失效、取消/成员数异常，以及真实报告调用入口。

MySQL批量读取测试运行实际SQL构造及扫描路径，检查单次查询和水位参数；不依赖生产库。数据库集成测试仍须配置隔离的本地`*_test`库，真实探针告警和真实模型效果验收仍需实际环境。

```sh
go test ./evidence ./traffic/internal/service ./traffic/internal/store ./traffic/internal/client ./traffic -count=1
go vet ./evidence ./traffic/internal/service ./traffic/internal/store ./traffic/internal/client
```
